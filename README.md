# Local View B3D / B3D Publisher

Локальный Publisher для БАЗИС 24. Его production-задача — получить **уже построенную БАЗИС геометрию модели** через официальный Script API и создать один автономный HTML-файл для передачи заказчику.

## Production-маршрут

```text
B3D-Publisher.exe
  → БАЗИС 24 открывает исходную модель
  → официальный BAZIS Script API
  → TObject3D / TTriMesh / TTriangleList / T3DTriangle
  → готовые вершины, нормали и UV БАЗИС
  → материалы и доступные локальные текстуры
  → один *_просмотр.html
```

В production **не используются**:

- реконструкция геометрии из B3D;
- собственное построение панелей, пазов, спилов или вырезов;
- OBJ, 3DS или DAE как промежуточный формат;
- WebViewer cloud или иная облачная служба;
- обход лицензирования/ограничений БАЗИС;
- внешние JavaScript/CSS/CDN-зависимости итогового HTML.

Если официальный Script API в конкретной установке БАЗИС недоступен, Publisher останавливается. Он не переключается на запрещённый обходной маршрут.

## Что получает заказчик

Только один файл:

```text
<имя модели>_просмотр.html
```

Заказчику не нужны БАЗИС, B3D-Publisher, плагины, отдельные текстуры, сервер или интернет. HTML содержит геометрию и поддерживаемые текстуры внутри себя и открывается локально в современном браузере с WebGL.

## Геометрия

`host/B3DPublisherHost/Bazis24FinalMeshPublisher.js` читает финальную полигональную геометрию непосредственно из объектов БАЗИС:

- `IsMesh()` / `AsMesh()`;
- `TTriMesh.TriLists`;
- `TTriangleList.Triangles`;
- `T3DTriangle.Vertex1/2/3`;
- `Normal`, `Normal1/2/3`;
- `TexCoord1/2/3`;
- `ToGlobal()` и `NToGlobal()` для мировых координат.

Панели БАЗИС наследуют полигональный слой через иерархию `TFurnPanel → TSolidBody → TTriMesh`, поэтому Publisher забирает геометрию, уже сформированную ядром БАЗИС, а не повторяет его операции.

## Материалы и текстуры

Для поверхности сохраняются данные материала, которые предоставляет БАЗИС. Publisher использует имя/цвет материала и, когда `TMaterial.PathAbsolute()` указывает на локальное изображение поддерживаемого браузером формата, встраивает файл в HTML как `data:` URI.

Поддерживаемые сейчас растровые форматы: PNG, JPEG, WebP, GIF и BMP. Если БАЗИС не предоставляет пригодную локальную текстуру, поверхность остаётся с цветом материала — никакая текстура не назначается по догадке.

## Вьювер

Итоговый HTML полностью автономен и содержит собственный WebGL-вьювер:

- перспективный вид;
- спокойное ограниченное вращение без авто-анимации;
- панорамирование и масштабирование;
- «Вписать»;
- отображение характерных рёбер без диагоналей триангуляции;
- режим прозрачности;
- точное выделение по клику через GPU picking;
- все поверхности одного объекта БАЗИС выделяются как одна деталь;
- «Снять выделение» и `Esc`;
- WebGL2 и WebGL1 fallback;
- корректная работа NPOT-текстур в WebGL1.

## B3D-Publisher.exe

Windows-host находится в:

```text
host/B3DPublisherHost/
```

Он:

1. предлагает выбрать `.b3d`;
2. устанавливает встроенный `Local View B3D Publisher.js` в стандартную папку скриптов БАЗИС;
3. открывает модель штатной ассоциацией Windows;
4. вызывает команду Publisher через интерфейс БАЗИС;
5. ждёт создания `<имя>_просмотр.html` рядом с моделью;
6. проверяет автономность HTML;
7. создаёт текстовую квитанцию с SHA-256 для локального контроля результата.

Клиенту EXE не передаётся — EXE нужен только на рабочем компьютере, где установлен БАЗИС.

## Сборка и release gate

GitHub Actions собирает self-contained single-file Windows x64 executable:

```text
B3D-Publisher.exe
SHA256.txt
```

Перед выпуском workflow проверяет:

- наличие встроенного официального BAZIS mesh-bridge;
- использование `TTriMesh`/`TTriangleList`/`T3DTriangle`;
- отсутствие WebViewer/CFRN production-маршрута;
- отсутствие OBJ/mesh-format export route;
- отсутствие старых автоматических PE/CFRN-инспекторов;
- синтаксис JavaScript;
- UX-контракт вьювера;
- офлайн-контракт;
- успешную `.NET` single-file сборку.

## Исследовательские каталоги

В репозитории сохранены более ранние исследования формата B3D:

```text
parser/
geometry/
publisher/
docs/
samples/
```

Они нужны для регрессий и документирования исследования формата. **Они не являются production-маршрутом B3D-Publisher и не используются для геометрии итогового клиентского HTML.**

Это разделение намеренное: исследование B3D можно продолжать независимо, но production Publisher остаётся на официальной финальной геометрии БАЗИС.
